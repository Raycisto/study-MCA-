Detailed topic-wise explanations for all five units

1.1 Introduction & Memory Allocation

▾

Data is raw, unprocessed facts (42, "Alice", 3.14). Information is processed, meaningful data. A Data Structure is a systematic way of organizing and storing data so it can be accessed and modified efficiently.

Classification of Data Structures
  • Primitive: int, float, char, double — hold a single value, provided by the language
  • Non-Primitive: arrays, linked lists, stacks, queues, trees, graphs — hold multiple related values
  • Linear: Elements in sequence (array, stack, queue, linked list) — each element has one predecessor and one successor
  • Non-Linear: Hierarchical or network arrangement (trees, graphs) — one element can have multiple successors
  • Static: Fixed size at compile-time (arrays)
  • Dynamic: Size changes at runtime (linked list, tree)
Abstract Data Type (ADT)

An ADT defines data + operations mathematically, without specifying how it is implemented. The Stack ADT defines push/pop/peek without saying whether it uses an array or linked list. ADTs let us think about what operations do, not how.

Pointer Basics & Dynamic Memory
  • Pointer: Variable storing the address of another variable. int *p = &x;
  • malloc(size): Allocates size bytes on the heap — uninitialized, returns NULL on failure
  • calloc(n, size): Allocates n×size bytes, zero-initialized
  • realloc(ptr, size): Resize existing allocation
  • free(ptr): Release memory — forgetting this causes a memory leak
⚠️ Pitfalls: Memory leak (no free), dangling pointer (use after free), NULL dereference (forgot to check malloc return). Always initialize pointers to NULL.
💡 Exam Tip: Linear structures access elements sequentially. Non-linear allow branching. ADT = logical description only. malloc returns void* — always cast it.

1.2 Stacks & Expressions

▾

A Stack follows LIFO — Last In, First Out. The most recently pushed element is always the first to be popped. Think of a stack of plates.

Core Operations
  • push(x): Insert x at the top — O(1)
  • pop(): Remove and return top element — O(1)
  • peek()/top(): View top element without removing — O(1)
  • isEmpty(): Check if stack has no elements
Array vs Linked Representation

Array: Uses TOP variable (starts at -1). Push: arr[++TOP]=x. Pop: return arr[TOP--]. Full when TOP==MAX-1. Stack overflow = push on full stack. Underflow = pop on empty.

Linked List: HEAD = TOP. Push = create node, make it head. Pop = remove head. No overflow. Uses extra pointer memory.

Expression Notations
  • Infix: A+B — natural for humans, needs precedence rules
  • Prefix (Polish): +AB — operator before operands
  • Postfix (Reverse Polish): AB+ — operator after operands, ideal for computers
Infix → Postfix Algorithm
  1. Operand → directly output
  2. '(' → push on stack
  3. ')' → pop and output until '(', discard '('
  4. Operator → pop/output operators of ≥ precedence from stack, then push current
  5. End → pop all remaining operators
📌 Precedence: ^ (3) > */ (2) > +- (1)
A+B*C-D → ABC*+D- | (A+B)*(C-D) → AB+CD-* | A*(B+C)/D → ABC+*D/
Applications
  • Infix→Postfix conversion and Postfix evaluation
  • Balancing parentheses in compilers
  • Function call stack (recursion)
  • Undo/Redo, Browser back button, DFS traversal

1.3 Queues & Variations

▾

A Queue follows FIFO — First In, First Out. Elements are inserted at REAR and removed from FRONT, like a checkout queue.

Operations
  • enqueue(x): Insert at REAR — O(1)
  • dequeue(): Remove from FRONT — O(1)
  • peek()/front(): View FRONT without removing — O(1)
Linear Array Queue Problem

FRONT and REAR both start at -1. After repeated enqueue/dequeue, FRONT moves right — leaving unused space at the start. The array appears full even when empty slots exist at the beginning.

Circular Queue (Solution)

Treats the array as a ring using modulo: REAR = (REAR+1) % MAX, FRONT = (FRONT+1) % MAX. Full when (REAR+1)%MAX == FRONT. One slot is left empty to distinguish full from empty. Holds MAX-1 elements.

Deque (Double-Ended Queue)
  • Insertions and deletions at BOTH ends
  • Input-restricted: Insert at one end only, delete from both
  • Output-restricted: Delete from one end only, insert at both
Priority Queue

Each element has a priority. Higher priority elements dequeue first. Ties resolved by FIFO. Best implemented with a Binary Heap for O(log n) insert and extract.

Implementation Insert Delete-Max
Unsorted Array O(1) O(n)
Sorted Array O(n) O(1)
Binary Heap O(log n) O(log n)
💡 Applications: CPU scheduling, print spooling, keyboard buffering, network packets, BFS traversal. Priority Queue used in Dijkstra's, Prim's, Huffman coding.

1.4 Linked Lists

▾

A Linked List is a chain of nodes. Each node has a data field and a next pointer. The last node's next = NULL. A HEAD pointer always points to the first node.

Singly Linked List
Operation Time Note
Insert at head O(1) Update HEAD
Insert at tail O(n) Traverse to end
Delete by value O(n) Find previous node first
Search O(n) Linear scan from head
Access by index O(n) No random access
Doubly Linked List (Two-Way)

Each node has prev + data + next. Enables bidirectional traversal. Deletion is easier (no need to track previous node). Two-Way Header List adds dummy header at start AND end to eliminate all boundary edge cases.

Circular Linked List

Last node's next → first node (HEAD). No NULL pointer. Traversal is infinite — detect loop by comparing with HEAD. Used in round-robin CPU scheduling, ring buffers.

Header Linked List
  • Grounded Header: Dummy header at start, last node = NULL — simplifies insertion at head (no special case for empty list)
  • Circular Header: Header at start, last node → header — combines benefits of circular and header lists
📌 Advantages over arrays: dynamic size, O(1) insert/delete at known position. Disadvantages: no random access, extra pointer memory, poor cache performance.

2.1 Trees & Traversals

▾

A Tree is a non-linear hierarchical structure. Nodes are connected by edges with no cycles. Every tree has exactly one root, and every non-root node has exactly one parent.

Essential Terminology
  • Root: Topmost node — only node with no parent
  • Leaf (External node): Node with NO children
  • Internal node: Node with at least one child
  • Depth of node: Edges from root to that node (root = depth 0)
  • Height of tree: Edges on the longest root-to-leaf path
  • Degree of node: Number of children
  • Degree of tree: Maximum degree among all nodes
  • Level: Root at Level 1; level = parent's level + 1
  • Forest: A collection of disjoint trees
Binary Tree Types
  • Full/Strict: Every node has 0 or 2 children
  • Complete: All levels filled except possibly last, last level filled left to right. Used in heaps.
  • Perfect: All internal nodes have 2 children, all leaves at same level. n = 2^(h+1) - 1
  • Skewed: Every node has only one child — worst case, acts like linked list
Key Binary Tree Properties
  • Max nodes at level i = 2^i
  • Max nodes in tree of height h = 2^(h+1) - 1
  • Min height for n nodes = ⌊log₂n⌋
  • Number of NULL pointers in n-node tree = n + 1
Tree Traversals
  • Preorder (Root→L→R): Copy tree, serialize, prefix expression
  • Inorder (L→Root→R): Gives SORTED output for BST — most important property
  • Postorder (L→R→Root): Delete tree, evaluate expression trees
  • Level Order: BFS using a queue — visits level by level
📌 Example tree (1 root, 2-3 children, 4-5 grandchildren):
Preorder: 1 2 4 5 3 | Inorder: 4 2 5 1 3 | Postorder: 4 5 2 3 1 | Level: 1 2 3 4 5
General Tree → Binary Tree (First Child–Next Sibling)

Left child = first child of original node. Right child = next sibling of original node. The root has no right child (no siblings). This conversion is fully reversible.

Huffman's Algorithm (Data Compression)
  1. Count frequency of each character
  2. Put all characters in a min-priority queue (ordered by frequency)
  3. Extract two minimum-frequency nodes, merge them (sum of frequencies) as a new internal node
  4. Repeat until one node remains = root of Huffman tree
  5. Left edge = 0, Right edge = 1. Code = path from root to leaf
📌 A(5), B(2), C(1), D(3): C+B=3, D+3=6, A+6=11(root). A=0, D=10, B=110, C=111. Frequent chars get shorter codes (prefix-free / no ambiguity).

2.2 Graphs & Traversals (BFS / DFS)

▾

A Graph G(V, E) consists of vertices V and edges E connecting pairs. Graphs model social networks, road maps, internet routing, etc.

Graph Terminology
  • Directed (Digraph): Edges have direction — (u,v) ≠ (v,u)
  • Undirected: Edges have no direction — {u,v} = {v,u}
  • Weighted: Each edge has a numerical cost/weight
  • Degree: Number of edges on a vertex (in-degree + out-degree for directed)
  • Path: Sequence of distinct vertices connected by edges
  • Cycle: Path starting and ending at same vertex
  • Connected graph: Path exists between every pair of vertices
  • Complete graph: Every pair connected — n(n-1)/2 edges for n vertices
  • DAG: Directed Acyclic Graph — used for topological sort
Graph Representations
  • Adjacency Matrix: V×V array. adj[i][j]=1 if edge exists. Check edge: O(1). Space: O(V²). Good for dense graphs.
  • Adjacency List: Array of linked lists. Space: O(V+E). Find neighbors: O(degree). Good for sparse graphs — used in BFS/DFS.
BFS (Breadth-First Search)

Uses a Queue. Explores level by level. Guarantees shortest path in unweighted graphs. Time: O(V+E).

  1. Mark source visited, enqueue
  2. Dequeue u, process it
  3. For each unvisited neighbor v: mark visited, enqueue v
  4. Repeat until queue empty
DFS (Depth-First Search)

Uses a Stack (or recursion). Explores as deep as possible before backtracking. Used for cycle detection, topological sort. Time: O(V+E).

MST Algorithms
  • Kruskal's: Sort edges by weight, use Union-Find to avoid cycles. O(E log E). Better for sparse graphs.
  • Prim's: Grow MST from a vertex, always add minimum-weight edge to unvisited vertex. O(V²) or O(E log V) with heap. Better for dense graphs.
Shortest Path Algorithms
Algorithm Type Negative Weights Time
Dijkstra's Single-source No O(V²) / O(E log V)
Floyd-Warshall All-pairs Yes O(V³)
💡 Dijkstra: dist[source]=0, all others=∞. Greedily pick min-dist vertex, relax all its edges. Works ONLY with non-negative weights.

Floyd-Warshall: for each intermediate k: dist[i][j] = min(dist[i][j], dist[i][k]+dist[k][j])

2.3 Minimum Spanning Trees & Shortest Paths

▾

A Spanning Tree of G(V,E) is a subgraph that is a tree, includes ALL vertices, and has exactly V-1 edges. A Minimum Spanning Tree (MST) is the spanning tree with minimum total edge weight — it connects all cities (vertices) with minimum total road length (edge cost).

Kruskal's Algorithm — Step by Step
  1. Sort all edges by weight (ascending)
  2. Initialize Union-Find: each vertex is its own set
  3. For each edge (u,v,w) in sorted order: if u and v are in DIFFERENT sets → add edge to MST, union the sets
  4. Stop when MST has V-1 edges

Time: O(E log E). Works edge-by-edge. Better for sparse graphs.

Prim's Algorithm — Step by Step
  1. Start with any vertex, add to MST set
  2. Among all edges connecting MST to non-MST vertices, pick minimum weight edge
  3. Add that vertex to MST set
  4. Repeat until all V vertices are in MST

Time: O(V²) with matrix, O(E log V) with heap. Works vertex-by-vertex. Better for dense graphs.

📌 MST has exactly V-1 edges. If all weights distinct → unique MST. Kruskal = global edge sorting. Prim = local vertex growth. Both give same total weight.

3.1 Asymptotic Notations

▾

When analyzing algorithms, we describe how resource usage grows with input size n. We ignore constants and low-order terms, focusing on growth rate.

Big-Oh O(g(n)) — Upper Bound (Worst Case)

f(n) = O(g(n)) means: ∃ constants c, n₀ such that f(n) ≤ c·g(n) for all n ≥ n₀. "This algorithm never does worse than this." Example: 3n²+5n+7 = O(n²).

Big-Omega Ω(g(n)) — Lower Bound (Best Case)

f(n) = Ω(g(n)) means: ∃ constants c, n₀ such that f(n) ≥ c·g(n) for all n ≥ n₀. "This algorithm always takes at least this long."

Big-Theta Θ(g(n)) — Tight Bound (Exact)

f(n) = Θ(g(n)) means f(n) = O(g(n)) AND f(n) = Ω(g(n)). Both upper and lower bounds match. ∃ c₁, c₂, n₀ such that c₁·g(n) ≤ f(n) ≤ c₂·g(n).

Growth Rates — Slowest to Fastest
Notation Name Example
O(1) Constant Array access, stack push/pop
O(log n) Logarithmic Binary search, BST ops
O(n) Linear Linear search, traversal
O(n log n) Linearithmic Merge sort, Quick sort (avg)
O(n²) Quadratic Bubble, Selection, Insertion sort
O(n³) Cubic Floyd-Warshall
O(2ⁿ) Exponential Recursive Fibonacci (naive)
O(n!) Factorial Travelling Salesman brute force
📌 Simplification rules: Drop constants (100n → O(n)). Drop lower-order terms (n²+n → O(n²)). Log base doesn't matter (log₂n = log₁₀n = O(log n)).

Best/Worst/Average case: Best = most favorable input. Worst = least favorable. Average = expected over all inputs.

3.2 Basic Sorting Algorithms

▾
Bubble Sort

Repeatedly compare adjacent elements and swap if out of order. After pass i, the i-th largest element is in its correct position. Optimization: use a swapped flag — if no swaps in a pass, exit early.

  • Best (already sorted + flag): O(n)
  • Average/Worst: O(n²)
  • Stable | In-place | Adaptive (with flag)
Selection Sort

Find the minimum of the unsorted portion and swap it to position i. Repeat for all positions.

  • All cases: O(n²) — always makes n(n-1)/2 comparisons
  • Makes at most n-1 swaps — fewest writes of the three
  • Unstable | In-place | NOT adaptive
  • Useful when writes are expensive (e.g., flash memory)
Insertion Sort

Build sorted array one element at a time. For each element, find its correct spot in the sorted portion by shifting larger elements right.

  • Best (sorted): O(n)
  • Worst (reverse sorted): O(n²)
  • Stable | In-place | Adaptive — very fast for nearly-sorted data
  • Used in Timsort (Python), Introsort (C++ std::sort) for small subarrays
📌 Quick memory aid:
Bubble = swap neighbors repeatedly | Selection = pick min, place at front | Insertion = insert card into sorted hand

3.3 Advanced Sorting Algorithms

▾
Quick Sort

Divide-and-conquer: choose a pivot, partition array so everything left of pivot < pivot, everything right > pivot. Recursively sort both sides.

Lomuto Partition (last element as pivot): i = low-1. For j from low to high-1: if arr[j] ≤ pivot → i++, swap arr[i] & arr[j]. Swap arr[i+1] with arr[high]. Return i+1.

  • Best/Average: O(n log n) — balanced partitions
  • Worst: O(n²) — pivot is always min or max (sorted/reverse input)
  • Space: O(log n) recursion stack
  • Unstable | In-place | Fastest in practice due to cache efficiency

Pivot strategies: First/last (simple but bad for sorted), Random (avoids worst case), Median-of-three (best in practice).

Merge Sort

Divide array at midpoint → recursively sort each half → merge the two sorted halves. Merge: compare front of each half, pick smaller, advance pointer.

  • All cases: O(n log n) — guaranteed, never degrades
  • Space: O(n) — needs temporary array for merge step
  • Stable | NOT in-place | Preferred for linked lists and external sorting
Sort Best Avg Worst Space Stable
Bubble O(n) O(n²) O(n²) O(1) Yes
Selection O(n²) O(n²) O(n²) O(1) No
Insertion O(n) O(n²) O(n²) O(1) Yes
Quick O(n log n) O(n log n) O(n²) O(log n) No
Merge O(n log n) O(n log n) O(n log n) O(n) Yes

4.1 Binary Search Trees & AVL Trees

▾
Binary Search Tree (BST) Property

For every node N: ALL values in left subtree < N.data AND ALL values in right subtree > N.data. This holds recursively. Inorder traversal of BST = Sorted (ascending) output — most critical property.

BST Operations
  • Search: Start at root. Go left if value < root, right if > root. O(h) where h = height.
  • Insert: Search until NULL position is found, insert new node there. Always inserts as a leaf.
BST Deletion — 3 Cases (Must Know!)
  • Case 1 — Leaf: Simply remove the node (set parent pointer to NULL)
  • Case 2 — One child: Replace node with its single child
  • Case 3 — Two children: Find inorder successor (smallest node in right subtree = leftmost of right child). Copy its value here. Delete the inorder successor (it's always Case 1 or 2).
Operation Balanced (avg) Skewed (worst)
Search/Insert/Delete O(log n) O(n)
Threaded BST

In a BST with n nodes, there are n+1 NULL pointers. A Threaded BST uses these NULL pointers to store inorder successor (right thread) or predecessor (left thread). Enables inorder traversal without a stack or recursion. Each node needs an extra boolean flag to distinguish real child from thread pointer.

AVL Tree — Height-Balanced BST

Balance Factor (BF) = height(left subtree) - height(right subtree). AVL requires BF ∈ {-1, 0, +1} for every node. If BF becomes ±2, rebalance using rotations. Guarantees O(log n) height always.

The Four AVL Rotations
  • LL Case (BF=+2, left-left): Single Right Rotation at unbalanced node
  • RR Case (BF=-2, right-right): Single Left Rotation at unbalanced node
  • LR Case (BF=+2, left-right): Left Rotate at left child, then Right Rotate at root
  • RL Case (BF=-2, right-left): Right Rotate at right child, then Left Rotate at root
📌 Memory trick: LL→Right, RR→Left, LR→Left-then-Right, RL→Right-then-Left
"Rotate in the OPPOSITE direction of the imbalance. Double rotation for mixed cases."

4.2 Heaps

▾

A Heap is a complete binary tree satisfying the heap property. It is the most efficient Priority Queue implementation.

  • Max-Heap: Parent ≥ children. Root = MAXIMUM element.
  • Min-Heap: Parent ≤ children. Root = MINIMUM element.
Array Representation (0-indexed)
  • Left child of i = 2i+1
  • Right child of i = 2i+2
  • Parent of i = ⌊(i-1)/2⌋
  • Last non-leaf = ⌊n/2⌋-1 (start heapify here for build-heap)
Heap Operations
  • Insert O(log n): Add at end → bubble up (heapify-up): compare with parent, swap if needed, repeat
  • Extract-Max/Min O(log n): Remove root → move last element to root → bubble down (heapify-down): compare with children, swap with larger/smaller, repeat
  • Peek O(1): Just return root element
  • Build-Heap O(n): Start from last non-leaf, heapify-down each node up to root. O(n) — NOT O(n log n)!
Heap Sort
  1. Build Max-Heap from array — O(n)
  2. Swap root (max) with last element, reduce heap size
  3. Heapify-down the new root — O(log n)
  4. Repeat step 2-3 until heap is empty

Total: O(n log n) | In-place | Unstable | Not cache-friendly

4.3 Hashing & Collision Resolution

▾

Hashing maps keys → array indices using a hash function, targeting O(1) average time for search, insert, delete.

Common Hash Functions
  • Division Method: h(k) = k mod m. Choose m as a prime not close to a power of 2.
  • Multiplication Method: h(k) = ⌊m × (k×A mod 1)⌋, A≈0.618 (golden ratio)
  • Mid-Square: Square the key, extract middle digits as hash
  • Folding: Split key into parts, add them, take mod m
Collision Resolution

A collision = two keys hash to same index. Inevitable when n > m (Pigeonhole Principle).

  • Linear Probing: h(k,i) = (h(k)+i) mod m. Try next slot sequentially. Simple but causes primary clustering — long chains of occupied slots form.
  • Quadratic Probing: h(k,i) = (h(k)+c₁i+c₂i²) mod m. Less clustering than linear but secondary clustering possible.
  • Double Hashing: h(k,i) = (h₁(k) + i×h₂(k)) mod m. Uses second hash for step size. Best open addressing method — no clustering.
  • Chaining (Separate Chaining): Each slot = linked list. Colliding elements chain together. Load factor can exceed 1. Simple but uses extra pointer memory.
Load Factor & Rehashing

Load factor α = n/m. Keep α < 0.7 for performance. When threshold exceeded: rehash — create 2× sized table (new prime), re-insert all elements. Cost O(n) amortized to O(1) per insertion.

Method Avg Search Worst Clustering
Linear Probing O(1) O(n) Primary
Double Hashing O(1) O(n) None
Chaining O(1+α) O(n) None

5.1 File Structures & Organization

▾

Data in file systems is organized as: Bit → Byte → Field → Record → File → Database.

  • Field: Single data attribute (student name, roll number)
  • Record: Complete set of related fields describing one entity
  • File: Collection of related records on secondary storage
  • Key field: Uniquely identifies a record (primary key)
File Operations
  • Create: New empty file, allocate disk space
  • Open/Close: Prepare for I/O / flush and release
  • Read/Write: Transfer data between memory and disk
  • Update: Modify an existing record
  • Delete: Remove a record (logical or physical)
  • Append: Add records at end of file
  • Seek: Move file pointer to a specific byte position
File Organization Methods
  • Sequential: Records stored one after another in sorted key order. Search: O(n). Best for batch processing. Worst for frequent random access.
  • Relative/Direct: Records accessed by position. Address = base + (N-1) × record_size. O(1) access. Wastes space if record numbers sparse.
  • Random/Hashed: Hash function maps key → disk address. Near O(1) by key. No ordering preserved.
ISAM — Indexed Sequential Access Method

Maintains: (1) main data file in sorted order and (2) separate index file with (key, disk-address) pairs. To find a record: binary search the index → jump to approximate location → sequential scan to find exact record. Supports both batch sequential access AND fast direct access. Limitation: Static index — heavy insertions fill overflow areas, degrading performance.

Direct Mapping Techniques
  • Absolute addressing: Physical disk address stored directly — not portable
  • Relative addressing: Offset from start of file — portable, file can move
  • Indexed sequential: ISAM-style — index provides relative address
💡 When to use which: Sequential → batch jobs. Relative → record numbers are natural keys. Hashed → fast key lookup, no ordering needed. ISAM → need both sequential and direct access.

5.2 Indexed Structures (B-Trees & B+ Trees)

▾
M-Way Search Trees

Generalizes BST: each node has up to M children and M-1 keys. Height = O(log_M n). BST is a 2-way search tree. With M=100 and n=1,000,000 records → height ≈ 3 disk reads to find any record.

B-Tree of Order m

Self-balancing M-way search tree designed for disk. All leaves at same level = always height-balanced.

Properties:

  • Every node has at most m children and m-1 keys
  • Every non-root node has at least ⌈m/2⌉ children
  • Root has at least 2 children (if not a leaf)
  • All leaves at same depth

Insertion: Find leaf, insert key. If node overflows (m keys) → split at median → push median UP to parent. If parent overflows → split again. If root splits → tree height increases by 1.

Deletion: (1) If key in leaf and node still has ≥ ⌈m/2⌉-1 keys → remove directly. (2) If key in internal node → replace with inorder predecessor/successor, delete from leaf. (3) Underflow → borrow from sibling via parent, or merge with sibling + pull down parent key.

B+ Tree (Used in Databases)

All data stored only at leaf level. Internal nodes = keys only (routing guides). All leaves linked as a doubly linked list.

Feature B-Tree B+ Tree
Data in All nodes Leaf nodes only
Leaf linking No Yes — linked list
Range queries Slow Very fast
Internal capacity Lower Higher (keys only)
Used in File systems MySQL, PostgreSQL, Oracle
📌 B+ Tree leaves: traverse linked list for range queries (e.g., all records where ID between 100 and 200). O(log n + output_size). This is why ALL major database systems use B+ trees as their primary index structure.

Quick Answers & Cheat Sheet

Key formulas, comparisons, and quick walkthroughs for exams

Quick Sort — Worst Case

Time: O(n²)
Occurs when pivot is always the smallest or largest element (already sorted / reverse sorted).
Average & Best: O(n log n)

Hashing — Complexity

Insert / Search / Delete:
Average: O(1)
Worst case (all collide): O(n)
Space: O(n)

DFS vs BFS — At a Glance

DFS uses a Stack (or recursion). BFS uses a Queue.
DFS: Time O(V+E), Space O(V)
BFS: Time O(V+E), Space O(V)
BFS guarantees shortest path in unweighted graphs.

Union-Find C Code — Quick Ref

Find: follow parent[] up to root + path compression: flatten tree.
Union: merge two sets + union by rank: attach smaller tree under root of bigger tree.
Time: O(α(n)) ≈ O(1) amortized (α = inverse Ackermann).

    printf("Postfix: ");
    for(int i=0; expr[i]; i++){

            pop(); /* discard ( */
        } else {

                printf("%c",pop());
            push(c);
        }
    }
    while(!isEmpty()) printf("%c",pop());

");
}

/*
 * swapPairs — swaps adjacent nodes in pairs by POINTER manipulation
 * Example: 1 -> 4 -> 3 -> 2 -> 5 -> NULL
 * Result:  4 -> 1 -> 2 -> 3 -> 5 -> NULL
 */
Node* swapPairs(Node *head) {
    if (!head || !head->next) return head;

    Node *prev = NULL;
    Node *cur  = head;
    Node *newHead = head->next;

    while (cur && cur->next) {
        Node *first  = cur;
        Node *second = cur->next;

        if (prev) prev->next = second;

        first->next  = second->next;
        second->next = first;

        prev = first;
        cur  = first->next;
    }
    return newHead;
}

Node* reverseIter(Node *h) {
    Node *prev = NULL, *cur = h, *nxt;
    while(cur) {
        nxt     = cur->next;
        cur->next = prev;
        prev    = cur;
        cur     = nxt;
    }
    return prev;
}

/* ── Recursive Reverse ── */
Node* reverseRec(Node *h) {
    if(!h || !h->next) return h;
    Node *rest = reverseRec(h->next);
    h->next->next = h;
    h->next   = NULL;
    return rest;
}

/*
 * deleteAlternate — deletes every alternate (even-positioned) node
 * Input:  1 -> 2 -> 3 -> 4 -> 5 -> NULL
 * Output: 1 -> 3 -> 5 -> NULL
 */
void deleteAlternate(Node *head) {
    if (!head) return;

    Node *cur = head;
    while (cur != NULL && cur->next != NULL) {
        Node *temp = cur->next;       /* node to delete */
        cur->next = temp->next;       /* skip over it */
        free(temp);                   /* free memory */
        cur = cur->next;              /* move to next kept node */
    }
}
C — Split Circular Linked List 
/*
 * Given: ptr pointing to a circular linked list.
 * Task:  Split it into TWO circular linked lists.
 * Uses slow-fast pointer to find the middle.
 */
void splitCircularList(Node *ptr, Node **head1, Node **head2) {
    if (!ptr) return;

    Node *slow = ptr, *fast = ptr;

    /* Move fast by 2, slow by 1 to find mid */
    while (fast->next != ptr && fast->next->next != ptr) {
        slow = slow->next;
        fast = fast->next->next;
    }

    /* If even nodes, move fast one more step */
    if (fast->next->next == ptr)
        fast = fast->next;

    /* Set heads */
    *head1 = ptr;
    *head2 = slow->next;

    /* Make both circular */
    fast->next = *head2;
    slow->next = *head1;
}

    while(i<n1)a[k++]=L[i++];
    while(j<n2)a[k++]=R[j++];
}

void mergeSort(int a[],int l,int r){
    if(l<r){
        int m=(l+r)/2;
        mergeSort(a,l,m);
        mergeSort(a,m+1,r);
        merge(a,l,m,r);
    }
}

After:  "); for(int i=0;i<n;i++)printf("%d ",a[i]);

🔥 #5 — Quick Sort
C — Quick Sort Complete
#include <stdio.h>

void swap(int*a,int*b){int t=*a;*a=*b;*b=t;}

int partition(int a[],int lo,int hi){
    int pivot=a[hi], i=lo-1;
    for(int j=lo;j<hi;j++)
        if(a[j]<=pivot) swap(&a[++i],&a[j]);
    swap(&a[i+1],&a[hi]);
    return i+1;
}

void quickSort(int a[],int lo,int hi){
    if(lo<hi){
        int p=partition(a,lo,hi);
        quickSort(a,lo,p-1);
        quickSort(a,p+1,hi);
    }
}

int main(){
    int a[]={10,80,30,90,40,50,70},n=7;
    quickSort(a,0,n-1);
    printf("Sorted: ");
    for(int i=0;i<n;i++)printf("%d ",a[i]);
    printf("
");
}
// Output
Sorted: 10 30 40 50 70 80 90
🔥 #6 — Floyd-Warshall All-Pairs Shortest Path
C — Floyd-Warshall Algorithm
#include <stdio.h>
#define V 4
#define INF 99999

void floydWarshall(int dist[V][V]){
    for(int k=0;k<V;k++)
        for(int i=0;i<V;i++)
            for(int j=0;j<V;j++)
                if(dist[i][k]+dist[k][j]<dist[i][j])
                    dist[i][j]=dist[i][k]+dist[k][j];
}

int main(){
    int graph[V][V]={
        {0,5,INF,10},
        {INF,0,3,INF},
        {INF,INF,0,1},
        {INF,INF,INF,0}
    };
    floydWarshall(graph);
    printf("Shortest distances:
");
    for(int i=0;i<V;i++){
        for(int j=0;j<V;j++)
            graph[i][j]==INF?printf("%4s","INF"):printf("%4d",graph[i][j]);
        printf("
");
    }
}

🔥 #7 — Heap Sort
C — Heap Sort (Max-Heap)
#include <stdio.h>

void swap(int*a,int*b){int t=*a;*a=*b;*b=t;}

void heapify(int a[],int n,int i){
    int largest=i, l=2*i+1, r=2*i+2;
    if(l<n&&a[l]>a[largest]) largest=l;
    if(r<n&&a[r]>a[largest]) largest=r;
    if(largest!=i){ swap(&a[i],&a[largest]); heapify(a,n,largest); }
}

void heapSort(int a[],int n){
    for(int i=n/2-1;i>=0;i--) heapify(a,n,i); /* Build max-heap O(n) */
    for(int i=n-1;i>0;i--){          /* Extract max O(n log n) */
        swap(&a[0],&a[i]);
        heapify(a,i,0);
    }
}

int main(){
    int a[]={12,11,13,5,6,7},n=6;
    heapSort(a,n);
    printf("Heap Sorted: ");
    for(int i=0;i<n;i++)printf("%d ",a[i]);
    printf("
");
}
// Output
Heap Sorted: 5 6 7 11 12 13
